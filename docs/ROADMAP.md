# 路线图

EmiyaAgent 的路线图以发布门槛和风险优先级排序，不承诺固定日期。项目当前处于 `0.x` Alpha；“已实现”表示代码中已有对应能力，不代表安全审计完成或 API 已稳定。

## 当前基线

当前实现已经覆盖：

- 多 provider、多角色自主路由及下一跳模型语言感知翻译；
- content-block 工具循环、并行只读工具和交互审批；
- shell 规则、策略 Hook、MCP 与可选 LSP；
- 前台子 agent、有界后台队列和 general 任务 Git worktree；
- 容错会话、命名检查点、分叉 lineage、项目记忆和上下文压缩；
- JSON/NDJSON CLI、稳定退出码以及共享轮次、总超时和 USD 预算；
- 工作区路径约束、环境白名单及 Windows/POSIX 进程树清理。

这些能力缩小了与成熟编码代理在自动化、会话管理、策略扩展和语义导航方面的差距。仍需通过发布工程、兼容性测试、可观测性和真实场景评测证明其可靠性。

## P0：首次公开发布阻断项

以下项目完成前，不应把当前 Alpha 宣称为稳定公开发行版：

- **选择并添加明确的 SPDX 许可证。** 仓库当前不应被假定为可复制、修改或再分发；许可证类型是维护者的法律与治理选择，不能由自动化代选。
- **已建立基础发布门禁。** Windows、macOS、Linux 与 Python 3.12/3.13/3.14 的锁定依赖矩阵执行 lint、单元测试、离线契约评测和 CLI 冒烟；其后独立构建并验证干净 wheel 安装。
- **扩展可复现的离线评测集。** 当前套件（9 个 contract）已覆盖正常工具执行、截断/预算阻断副作用、重复调用 ID、并行只读免审批、未知工具错误配对、串行批次中途取消、审批放行与审批拒绝；仍需加入代码检索、精确编辑、会话恢复、后台任务和机器输出的端到端案例。
- 冻结 JSON/NDJSON `schema_version = "1"` 的字段语义，提供样例和兼容性测试；为未来 schema 升级定义并行支持或迁移政策。
- **已建立基础制品验证。** CI 构建 sdist/wheel，离线审计路径、类型、敏感文件、元数据及源码一致性，再在干净环境安装 wheel，并校验依赖、包元数据和已安装 CLI；签名与 provenance 仍待发布策略确定。
- 在仓库设置中启用并验证 GitHub Private vulnerability reporting，完成一次不公开的报告流程演练。
- **已建立依赖更新入口。** Dependabot 每周检查 uv 与 GitHub Actions，CI Actions 固定到完整提交；仍需明确发布签名、制品 provenance 和安全公告流程，在没有验证前不作供应链保证。
- **已完成首轮内部默认配置安全复核与回归测试。** 已覆盖未信任项目、路径/链接绕过、环境泄露、Hook 单调权限、LSP 冷启动审批及 shell/Hook/LSP 进程树生命周期；stdio MCP 的后代进程收容、第三方安全评估和真正的 OS 沙箱仍是明确的剩余边界。

## P1：可靠性与可诊断性

- **已提供第一层脱敏诊断**：`/doctor` 与 `emiya doctor [--json]` 报告版本、配置来源与警告、凭据来源（不含值）、路由可用性和 Hook/MCP/LSP/会话概览。仍需扩展为可导出的完整诊断包（退出原因、资源上限、组件运行态与历史），绝不包含 key 或完整会话。
- 为 Provider、MCP 和 LSP 增加协议级兼容性矩阵与本地 fake server 套件，覆盖乱序、坏帧、超时、EOF、限流和取消竞态。
- 扩展会话迁移与检查工具：只读验证、显式修复预览、备份/导出和可配置保留策略。
- 对后台任务增加重启后的元数据恢复、孤立 worktree 检测和安全的人工接管流程；不自动删除含改动目录。
- 改进预算模型：区分已承诺和已结算费用，显示路由定价来源，并为无定价模型提供显式的用户策略，而不是隐式估算。
- 建立性能基线：提示词缓存命中、首 token 延迟、工具吞吐、压缩成本、会话加载和大型仓库搜索；性能优化不得破坏确定性与边界检查。
- 加入故障注入测试，系统覆盖磁盘写满、权限变化、锁争用、子进程拒绝终止和网络半关闭。

## P2：生态与扩展能力

- 设计版本化插件接口，让 Provider、工具、Hook 和渲染扩展可以声明权限、数据流、生命周期与兼容版本；在此之前不承诺内部 Python API 稳定。
- 增加 MCP 能力审计与逐 server/tool 策略，清楚展示远端 endpoint、参数和返回数据去向。
- 改进 LSP server 发现、健康状态和多根工作区支持，同时保持“绝不隐式下载”和首次启动审批。
- 提供可选的外部沙箱后端接口（如用户自备容器/虚拟机/受限执行器）。即使实现该接口，也必须逐后端说明保证；当前 worktree 和进程组不会被重新命名为沙箱。
- 增加跨任务结果引用、显式合并/应用 worktree 改动的审阅流程，以及面向长任务的持久队列。任何自动合并或推送能力都必须单独授权。
- 提供更完整的可访问性、本地化和非交互文档，保证人类输出与机器协议继续严格分离。

## P3：稳定版候选

- 根据真实项目评测定义质量基线，并持续报告成功率、回归和已知失败模式，而不是只展示演示案例。
- 发布配置、会话与自动化协议的兼容性承诺和弃用周期。
- 完成第三方安全评估或公开威胁模型审阅，并解决阻断级问题。
- 建立维护者轮值、发布回滚和漏洞协调机制；具体治理模式由项目维护者决定。
- 在文档、安装体验、跨平台测试和升级路径达到发布标准后，再评估 `1.0`。

## 明确的非目标

- 不把模型输出视为可信指令或安全证明。
- 不通过隐藏审批、默认自动执行或静默扩大环境继承来追求“无摩擦”。
- 不自动下载并执行 LSP、MCP 或插件依赖。
- 不把 Git worktree、路径校验或 Job Object/进程组描述为 OS 沙箱。
- 不在缺少权威 usage/定价时声称预算绝对精确。
- 不由项目代码替维护者决定许可证、贡献者协议或社区治理政策。

路线图建议和优先级讨论可以使用 feature request 模板；涉及可利用的边界绕过请遵循 [安全政策](../SECURITY.md)，不要公开披露。
